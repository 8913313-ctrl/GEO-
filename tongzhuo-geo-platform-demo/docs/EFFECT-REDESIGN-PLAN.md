## 1. 用户反馈与现状问题（先对齐问题，再谈设计）

| # | 用户反馈 | 代码现状（证据） | 根因 |
|---|---|---|---|
| 1 | 没有接入第三方 API 时，页面效果很简单，第一眼不知道有什么作用 | 无数据时各视图只有 `effectMonitorEmptyState`「暂无已验收的 live evidence」+ 一条服务异常卡；没有任何"这是干什么的、怎么产生数据"的交代 | 空状态只描述"缺什么"，不描述"有什么用、下一步做什么" |
| 2 | 有些卡片内容是"查看"但没有实际效果 | `effectAlignedKpi`（effect.js:96-104）中 `action` 参数渲染 `<b>查看 →</b>` 纯文本，**无 data-action、无点击行为**；"竞品对比"卡恒为"—" | 骨架冗余 + 死交互占位 |
| 3 | 很多没用的内容本应在一个页面展示 | 品牌监测有 **11 个 view**（effect.js:776-788），其中 6 个洞察子视图（提及率/排名、舆情/情感、商品卡分析、AI 引用来源、AI 对话记录、作品引用追踪）无数据时均为同款空态页 | 信息架构过度拆分，视图数 > 实际可承载的内容数 |
| 4 | "灼见 AI 检测服务·服务异常"卡片在每一个页面都出现，不合理 | `effectRelayStatusPanel` 在 `renderEffectMonitor` 中对**每个非 dashboard 视图**渲染（effect.js:1609），实时搜索/品牌诊断页同样嵌入 | 环境状态（服务连接）被误当作页面内容反复渲染；异常文案也是晦涩的技术用语（"服务器处理请求失败，请查看服务日志"） |

**原则性约束（不可违背，来自 AIDSO-EFFECT-DETECTION-INTEGRATION.md / UI-STYLE-ARCHITECTURE.md）**：

- **不虚构数据**：未返回字段不得填演示数字/估算 KPI；空态占位只能用"结构说明"，不能用假数据勾勒。
- 样式走 `css/modules/effect.css` 的 `.effect-*` / `.route-effect-*` 作用域；遵循现有设计令牌（枫叶红 `--blue: #b8442f`、暖白背景）。
- 现有 `data-action` 体系与 `PAGE_META` 路由注册不动；`effect-monitor-view` / `effect-monitor-tab-group` 等 action 需保留兼容或改造映射。

## 2. 设计原则（本次改版的总纲）

1. **一页一任务**：每个路由页只有一个核心任务；其余信息以分区形式出现在同页，靠优先级（而非 tab 数量）组织。
2. **状态是环境，不是内容**：服务连接/额度/平台能力等环境状态收敛到页头一个状态点 +（异常时）一条可关闭的全局提示条；不再作为页面卡片。
3. **空状态 = 下一步引导**：每个空块必须回答三件事——「这块将显示什么」「数据从哪来」「现在点哪里开始」，并提供真实可点的 CTA。
4. **渐进披露**：尚无数据来源的视图（商品卡分析、舆情/情感等字段依赖上游返回）不占导航位置，导航里出现即代表当前有内容或该功能已可用。
5. **杀死亡交互**：任何看起来可点的元素必须真的触发动作（跳转/过滤/滚动/复制）；做不到就删掉。

## 3. 新信息架构

### 3.1 AI 效果：侧边栏一层平铺（96智见同款导航）

**现状**：`效果页签(实时搜索/品牌诊断/品牌监测) + 二级分组(概览/洞察分析▾6项/管理▾4项) + 三级内容`，品牌监测下 11 个视图，每个视图顶部重渲染服务状态卡。

**改为（用户确认：和 96 智见一样，分组标题下所有子主题一层平铺）**：

```
侧边栏「AI 效果」分组（改后，对齐96智见「数据监测」同款）：
├ 实时搜索          → #effect-search       （单问题实时检测）
├ 品牌诊断          → #effect-diagnostic   （冻结问题集批量诊断+报告）
├ 品牌监测          → #effect-monitor      （计划配置/运行/历史/导出/问题库——对应96"品牌监测配置"）
├ 数据看板          → #effect-dashboard    （聚合首页：KPI+趋势+平台+引用+最近对话）
├ 提及率 / 排名     → data-effect-view="mentions"
├ 舆情 / 情感       → data-effect-view="sentiment"
├ 商品卡分析        → data-effect-view="product-cards"
├ AI 引用来源       → data-effect-view="sources"
├ AI 对话记录       → data-effect-view="dialogs"
└ 作品引用追踪      → data-effect-view="works"
```

- **全部入口恒定可见**：任何状态下不隐藏、不折叠、不做下拉（96 智见做法，用户已确认）。
- **每个子主题 = 独立页面**：复用现有 `effectMonitor*View` 渲染函数；页内统一的「标题 + 筛选栏（品牌/平台/问题/时间）→ KPI → 表格/榜单 → 明细」结构（对齐96）；移除每页重复的服务状态卡，状态只在页头状态点 + 全局提示条。
- **数据看板 = 聚合首页**：KPI 行 + 提及率趋势 + 平台明细 Top5 + AI 引用来源 Top5 + 最近 AI 对话 + 作品/商品卡/舆情摘要，各块"查看更多"跳转到对应子主题页（对齐96"数据看板"的"查看详情→"跳转，不做同页展开——因为子主题页本身是独立页面）。
- **品牌监测页 = 计划管理**：计划卡（监测中/下次运行/冻结问题/额度/预计消耗）+ 创建/编辑计划表单 + 历史运行 + 导出 + AI 问题库；不再与数据看板混排。
- KPI 显示真实值：有口径显示 `0% / 0 次`，无口径显示 `—`；不隐藏、不伪造。
- 无计划/未接入时：各子页保持骨架（筛选栏/KPI/表头恒定），数据区显示「暂无数据 + 数据从哪来 + 下一步（去品牌监测创建计划/立即运行）」。绝不出现白页。

## 3.1b 竞品参考调研：96智见（geo.96.cn）监测模块结构

用户提供的竞品（供应商已真实运行、有数据）。其「数据监测」模块结构值得借鉴的点：

| 竞品做法 | 说明 | 我们借鉴 |
|---|---|---|
| 一级导航「数据监测」下平铺 8 个子菜单（品牌监测配置/数据看板/提及率及排名/品牌情感倾向/商品卡分析/引用源分析/AI对话记录/作品引用追踪），**永不隐藏** | 子主题永远可见 | 借鉴"永不隐藏"原则，但**不照搬侧边栏结构**——用户要求侧边栏一层 3 项，子主题改为看板内固定分区 |
| 每个子页统一「标题 + 筛选器（品牌/平台/问题/日期）」在首行 | 结构一致，用户学会一个页面就会用全部 | 采用：统一筛选栏组件（看板顶部） |
| 无数据时：指标显示 0% / 0 次（不是"—"也不是隐藏），表格/榜单保留表头 + 分页，数据区显示"暂无数据" | 页面始终"完整成形的样子"，只是没有内容 | 采用（兼容我们不虚构原则：指标显示真实 0 或"—"、结构不消失） |
| 数据看板（dashboard）= 全部子主题的摘要聚合（KPI 行 + 平台表现 + 榜单 + 趋势 + 商品卡 + 引用来源 + 对话记录），各自"查看更多/查看全部"跳到子页 | 一页看全 + 深度下钻 | 采用：品牌监测=单一聚合看板；"查看更多"改为同页展开（避免跳转页的重复感） |
| 指标口径提供"全部品牌"/"当前品牌"切换 | 让用户看到自己 vs 行业 | 部分采用（我们有品牌诊断的竞品对比边界，需谨慎） |

竞品不足（我们不学）：页面指标排布密集重复（看板与子页内容大量重复）、空态只有"暂无数据"四个字没有下一步引导、文案偏运营术语（"品牌提及好感度"等）没有解释口径。

### 3.2 实时搜索（改"对齐版"已有基础，做收敛）

**现状**：页头 + 4 KPI + 任务卡（内嵌服务状态大卡）+ 回答卡 + 诊断卡 + 平台表 + 历史 + 系统状态卡。

**改为**：

```
┌──────────────────────────────────────────────────────────────┐
│ 实时搜索 · 让品牌被 AI 准确看见                      [● 检测服务已连接] │
├──────────────────────────────────────────────────────────────┤
│ 检索框（聚焦主任务）：输入问题 → [开始检索]                        │
│ 平台 chips（仍在检索框下方，保持可见）                            │
├──────────────────────────────────────────────────────────────┤
│ [本次检索概览]（有结果时：覆盖平台/提及率/引用条数）                │
│ [AI 平台 · 实时回答]  ← 无结果时：显示"将展示什么"的结构说明       │
│ [本次检索诊断]        ← 同上                                    │
│ [各平台表现]          ← 同上                                    │
│ [最近检索历史]        ← 同上，点击历史=加载该次结果（已有逻辑）      │
└──────────────────────────────────────────────────────────────┘
```

- **删除**：KPI 四卡（含死"查看→"与恒"—"的竞品卡）——搜索页的主任务就是"搜"，不需要常驻 KPI；`系统状态`卡降级进页头状态点（`// 检测额度` 保留在页头 tooltip 或检索框下方一行小字）。
- **服务状态大卡**从任务卡内移除，改为页头状态点 + 异常提示条。
- KPI 若保留，则只保留 2 个真实有意义的数字（今日检测数 / 已验证回答数），且带点击行为（滚动到历史/结果区）。

### 3.3 品牌诊断

**现状**：开始页（品牌名+官网）→ 配置向导（品牌/竞品/问题集/能力/轮次）→ 报告；开始页前同样渲染服务状态卡。

**改为**：

```
┌──────────────────────────────────────────────────────────────┐
│ 品牌诊断 · 看清品牌在 AI 回答中的认知结构            [● 检测服务已连接] │
├──────────────────────────────────────────────────────────────┤
│ （首屏）价值一句 + 三步流程示意（配置→检测→报告）                  │
│ 开始表单：品牌名 [*] + 官网（可选）+ [开始配置]                   │

│ 诊断配置（同页分区：品牌 / 竞品 / 问题集 / 平台能力 / 采样次数）     │
│ 报价条（积分）→ [确认并提交]                                     │

└──────────────────────────────────────────────────────────────┘
```

- 移除开始页与服务状态卡；向导本身已是"单页多分区"，保留，但头部服务状态卡去掉。
- 诊断报告生成按钮已有真实逻辑（effect-diagnostic-generate-report），保留并前置。

## 5. 状态矩阵（每个状态的页面应有形态）

| 状态 | 页面形态 |
|---|---|
| 服务已接入 + 有计划 + 有证据 | 完整：计划卡/KPI/趋势/平台明细/引用/对话/运行 全量渲染 |

| 服务已接入 + 无计划 | 看板骨架完整；分区显示引导文案 + [去创建监测计划]；不隐藏任何导航与区块 |
| 服务未接入（无 API 凭据/异常） | 看板骨架完整 + 全局提示条（去系统设置）；KPI 显示"—"，分区显示「接入后你将看到：…」说明 |
| 演练模式（mock） | 与正常一致，仅在页头状态点旁标注"演练模式"，结果不能作为正式结论（复用现有 mock 提示） |

## 7. 已确认决策点（2026-08 用户确认）

1. **侧边栏 = 96智见同款一层平铺**：「AI 效果」分组标题下所有子主题直接平铺（实时搜索 / 品牌诊断 / 品牌监测 / 数据看板 / 提及率及排名 / 舆情情感 / 商品卡分析 / AI引用来源 / AI对话记录 / 作品引用追踪），**永不隐藏、不折叠、不做下拉**；复用现有 `data-nav="effect-monitor"` + `data-effect-view` 机制。
