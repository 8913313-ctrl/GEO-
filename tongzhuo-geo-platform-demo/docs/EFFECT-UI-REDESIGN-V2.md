## 0. 为什么是 v2（用户最新反馈 → 设计主线）

v1 解决了"状态卡重复 / 死交互 / 空态"等技术问题，但漏掉了用户真正在意的三件事。
这次反馈的核心："**别人家 GEO 后台一打开就能看到客户品牌在豆包、DeepSeek、千问等平台的排名信息，不管有没有，都让用户看到支持这些平台**"，以及"实时搜索页面**让我自己不会去豆包搜吗**"、"品牌监测 / 数据看板上**同一排页签条出现两次**"。

| 用户反馈 | 根因（代码证据） | v2 设计主线 |
|---|---|---|
| 看不到平台覆盖，看不出支持哪些 AI 平台 | 平台只在表单内以单字缩写 chips 出现（`effectAlignedCapabilityChips` / `effectSearchPlatforms`），无 logo、无状态、无"平台×品牌"展示；`EFFECT_RELAY_PLATFORM_UI`（monitoring-analysis.js:1724）只定义了单字缩写+颜色，从未被做成声明性展示 | **主线 A：平台矩阵优先** |
| "我为什么不自己去豆包搜，还要花钱在你这检测" | 实时搜索首屏 = 大标题 + 一个输入框 + "预计消耗 X 积分"灰字 + 服务异常大红条，**整个页面没有回答"我的价值是什么"** | **主线 B：价值主张前置** |
| 品牌监测页 & 数据看板页顶部都有同一排页签条（图4），侧边栏也有同样 8 项 | `effectMonitorViewTabs`（effect.js:791）在 `renderEffectMonitor` 每个视图顶部渲染 8 个 tab（dashboard/settings/mentions/sentiment/product-cards/sources/dialogs/works），而侧边栏（index.html:63-73）已经平铺了同样的 8 项 → 两套导航打架 | **主线 C：导航唯一** |
| 每个页面顶部重复大红条"检测服务未连接" | `effectRelayStatusPanel` 在每个非 dashboard 视图渲染大状态卡 | **主线 D：状态降噪** |

**红线（延续 v1，不可违背）**：
- 不虚构数据：未返回字段不填演示数字；"未提及"只能在有样本时下结论，无样本显示"待监测"中性态。**唯一例外 = 实时搜索"示例模式"**（见主线 B：无任何真实 evidence 时默认展示带「示例」标识的灰化效果，真实数据存在即整体替换移除标识）。
- 不破坏 `data-action` 体系与路由注册；样式走 `css/modules/effect.css` 的 `.effect-*` / `.pf-*` 作用域。
- "支持该平台"是**能力声明**（来自能力清单/内置布局），不是结果数据，可静态展示；但未接入服务时只能显示"接入后可用"灰态，不得写成"已支持"。

## 1. 三条主线详解

### A. 平台矩阵优先 —— 让"支持豆包 / DeepSeek / 千问"成为第一眼可见的事实

**新增两个全局组件，所有 AI 效果页面共享：**

**A1. `平台覆盖条 PlatformShelf`（页面级，固定在页头下方）**
一行横向排列全部平台，每个平台 = 官方风格 logo + 中文名 + 状态徽标，**恒显**（有无数据、是否接入都显示）：

```
┌ 平台覆盖 ─────────────────────────────────────────────────────────────┐
│ [豆包●检测中] [DeepSeek●已纳入] [千问●纳入] [Kimi●即将支持] [元宝●即将支持] │
│                                                        全部平台由检测能力配置决定 · 管理   │
└────────────────────────────────────────────────────────────────────────┘
```

平台状态徽标（5 态）：
| 状态 | 含义 | 颜色 |
|---|---|---|
| `已纳入`（绿） | 已有可验证证据（提及/未提及） | ✓ 绿 |
| `检测中`（蓝 脉冲） | 当前运行正在采样该平台 | ○ 蓝 |
| `待监测`（灰） | 能力已配置但尚无该平台样本 | — 灰 |
| `即将支持`（灰虚线） | 内置布局存在但当前客户能力清单未开通 | 灰虚线 |
| `未接入`（黄） | 检测服务未连接，无法判断 | ⚠ 黄 |

**A2. `平台 × 品牌 矩阵 PlatformMatrix`（数据看板核心卡 + 有结果时的搜索/诊断首页）**
每行一个平台：logo + 名称 + 终端（网页/手机/电商），每列 = 该平台的表现：

```
┌ 平台表现 ──────────────────────────────────────────────── 全部平台 ┐
│ 平台       提及   出现位置   引用来源   最近采样                    │
│ 豆包       ✓ 100%   #1       3 条       今天 10:32                 │
│ DeepSeek   ✓ 50%    #2       1 条       今天 10:32                 │
│ 千问       ✗ 0%     —        0 条       今天 10:32                 │
│ Kimi       待监测   —         —         尚无样本                   │
│ 元宝       即将支持 —         —         未开通                     │
└────────────────────────────────────────────────────────────────────┘
```

- 有真实数据：显示真实值（提及率 / 出现名次 / 引用条数）。
- 无样本：显示"待监测"中性态，**绝不写"未提及"**（避免把"没检测"说成"没出现"）。
- 未开通：显示"即将支持"，把平台覆盖面做成产品卖点（用户要的正是这个）。

### B. 实时搜索价值重定位 —— "默认给出效果，不靠说服"

v2 初稿的"你自己搜 vs 灼见"对比表已**否决**（用户反馈：不要列对比）。改为 **"默认即有效果"**：

- **默认状态 = 一次看得见的效果**：页面打开时检索区预填一个**后台生成的默认问题**（示例问题集，用户可改），结果区默认显示一组**标注为"示例"的检索效果**（平台表现矩阵 + 回答卡 + 引用来源），用户不用先提问就知道这条产品线能交付什么。
- **价值说明收成小按钮**：标题旁一个轻量「💡 为什么需要检测？」小按钮，点击弹出小面板说明 3 条价值：① 一次提问 → 豆包/DeepSeek/千问…N 平台同题采样；② 回答 + **引用来源与证据链**（AI 引用了哪篇内容、哪个链接、证据 ID）；③ **品牌视角 + 跨时间对比**（是否被提及、第几条、引用是否官网、上次未提及→这次提及）。平时不占首屏。
- **问题来源双通道**：检索输入框旁"使用默认问题 ▾"（后台生成的问题集，可下拉选择）；用户也可自由输入自己的问题。
- **示例值红线（替代 v1"绝无演示数据"）**：
  1. 示例数据必须带明显标识（「示例」徽标 + 灰化卡 + 页面注明"首次真实检测后自动替换"），绝不冒充真实结果；
  2. 一旦存在真实检测证据（含演练模式真实交付），示例整体被真实数据替换并去除标识；
  3. 示例仅存在于"无任何真实 evidence"的空状态，默认页=示例页，不可与真实数据并存。
- "本次预计消耗 X 积分"从畏缩的灰字升级为检索区内的正向说明：「本次将检测 3 平台 × 2 终端 = 6 项，预计消耗 X 积分」，与"开始检索"同权重。

### C. 导航唯一 —— 杀掉页面内页签条

- 侧边栏「AI 效果」分组 8 个平铺入口（index.html:63-73）**保留不动**，它是唯一导航。
- **删除 `effectMonitorViewTabs` 在所有视图顶部的渲染**（品牌监测、数据看板、6 个洞察子页一律不再出现页签条）。
- 每个子页面用**内容结构**区分职责，不再靠"又一排页签"：
  - 数据看板 = KPI 网格 + 平台矩阵 + 趋势 + 引用 Top5 + 最近对话摘要；
  - 监测设置 = 计划总览 + 配置表单 + 历史运行 + 问题库（分区）；
  - 提及率/排名 = 逐平台排行表；
  - 舆情/情感、商品卡分析、AI 引用来源、AI 对话记录、作品引用追踪 = 各自的表格/列表 + 统一筛选栏（品牌/平台/时间）。
- 区块之间跨页跳转用 `link-button`（"查看明细 →"），与侧边栏导航形成**单向**关系：页面内只向下钻取，不上来再加一层导航。

### D. 状态降噪 —— 服务状态收敛为页头胶囊

- `effectRelayStatusPanel` 大卡**不再作为页面内容渲染**。
- 页头统一一个状态胶囊：`● 检测服务已连接`（绿）/ `● 检测服务未连接`（黄，点击展开一行可读文案 +"去系统设置"）/ `演练模式`（描边灰）。
- 异常文案客户可读化："检测服务未连接，检测需要先完成服务配置"（技术细节进 tooltip），不再出现"服务器处理请求失败，请查看服务日志"直接糊在首屏。

| podo/design-agent-skills 7⭐ · ihlamury/design-skills 81⭐ | — | 排除（星标过低） |

**frontend-design 关键规则（重设计必须遵守）**：
1. **质量底线**：响应式到窄屏、键盘焦点可见、尊重 reduced-motion——不张扬但必须达标。
2. **hero = 主张**：首屏第一眼必须是"这一页的核心主张"，不用"大数字+小标签+渐变"模板答案糊弄（与主线 B 一致：实时搜索首屏=可运行的默认效果，不是解释文案）。
3. **把大胆用在一个地方**：每页一个"签名元素"（signature），其余保持安静克制（本次签名元素 = 品牌化平台 logo / 平台×品牌矩阵）。
4. **空态与错误是方向而非情绪**：空屏=行动的邀请（与 §1 空态原则一致）；错误信息明确"发生了什么、怎么修"，不道歉、不模糊。
5. **文案从用户侧命名**：用户管理的是"监测计划"，不是"任务项/运行快照"；按钮用主动语态（"开始检索"而非"提交"），动作名称全流程一致。
6. **避免 AI 默认脸**（奶油底+衬线大字+赤陶色、近黑底+荧光绿、报纸栏式）：本项目沿用品牌枫叶红，但要避免把页面做成"模板后台"。

## 3. 页面级线框图

## 4. 状态矩阵（每个状态的页面形态，延续 v1 并强化）

| 状态 | 平台覆盖条 | 平台矩阵 | KPI | 区块 |
|---|---|---|---|---|
| 已接入+有计划+有证据 | 全量状态 | 真实数据 | 真实值 | 全量 |
| 已接入+有计划+无证据 | 全部"待监测" | "待监测" | 真实 0 或"—" | 骨架+「立即运行」 |
| 已接入+无计划 | 显示能力平台 | "待监测" | "—" | 骨架+「去创建监测计划」 |
| 服务未接入 | **平台照常显示，状态="未接入"黄＋说明"接入后即可检测"** | 同左 | "—" | 骨架+「去系统设置」 |
| 演练模式 | 与正常一致 | 真实（mock 交付） | 真实值 | 页头胶囊标注"演练模式" |
| 实时搜索·无任何真实证据 | 全量 | **示例矩阵（「示例」徽标+灰化）** | 示例值（带标识） | 示例回答/引用骨架 + "首次真实检测后自动替换"注记 |

要点：**未接入/无计划时平台覆盖条与矩阵照样渲染**（这正是"不管有没有都让用户看到支持这些平台"），只是状态徽标为"未接入/待监测/即将支持"，绝不虚构"提及/未提及"。

## 6. 实施分期

**阶段 A（高优先，立竿见影）**
1. 平台视觉系统：`EFFECT_RELAY_PLATFORM_UI` 品牌化 + `.pf-*` 基础样式（logo/覆盖条/状态徽标）。
2. `pfPlatformShelf` 全页接入 + `effectMonitorViewTabs` 从所有视图移除（导航唯一）。
3. `effectRelayStatusPanel` → `pfStatusCapsule`，异常文案可读化。

**阶段 B（核心）**
4. 实时搜索首屏重构：默认问题预填（后台生成）+「💡为什么需要检测？」小按钮弹层 + 带 logo 平台选择卡 + 正向费用 + 无真实证据时的「示例模式」默认效果区（带标识、真实证据后整体替换）。
5. 数据看板重排（KPI 网格 + 平台矩阵 + 趋势 + Top5 + 最近对话）。
6. 监测设置/六个洞察子页：筛选栏 + 骨架 + 空态升级，无计划/未接入态平台恒显。

**阶段 C（打磨与回归）**
7. 深色/窄屏、演练模式、旧入口（工作台快捷卡、`effect-search-focus`、`effect-monitor-view` action 兼容）。
8. 回归验证：无虚构数字；页面内无伪按钮；任何子页不出现重复导航/大红卡。

**验收标准**
- 打开任意 AI 效果页面，第一眼能看到：这是什么页面 + 支持哪些 AI 平台 + 现在的状态。
- 实时搜索页首屏直接有可运行效果：默认问题已预填、无真实证据时展示带「示例」标识的默认效果；价值说明在小按钮弹层里，不占首屏。
- 全站页面内不存在与侧边栏重复的导航页签。
- 服务未接入时平台覆盖条照常显示（"未接入/即将支持"态），页面无大红条。
- 有证据才有"提及/未提及"，无样本只显示"待监测"。
