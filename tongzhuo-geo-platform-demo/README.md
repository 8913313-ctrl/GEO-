# 桐灼 GEO 运营系统 · 0.6 私有化运营底座

这是一个基于 GEOFlow 与 GEORank 源码能力重新编排的企业私有化运营系统。当前已补齐 SQLite 正式数据库、账号/角色/权限、会话与 CSRF、工作区版本锁、审计日志、API Key 加密、发布器配对、版本化企业知识、PDF/Office 解析、OCR 队列、可插拔向量后端、混合检索、引用证据、内容生产审核、官网 CMS，以及运营诊断第一阶段。运营诊断将 Citation Lab 固定研究基线、企业工作区实测和未来实时采样严格分层；当前不伪造品牌排名、推荐率或实时引用结论。

## 启动

```powershell
cd "G:\桐灼GEO运营\tongzhuo-geo-platform-demo"
npm start
```

浏览器打开 `http://127.0.0.1:43127`。

首次打开需要创建企业管理员。生产环境配置、反向代理、备份恢复和本地发布器配对请参阅 [私有化部署手册](docs/PRIVATE-DEPLOYMENT.md)。

## 推荐演示路径

### 1. 首次建档

```text
工作台
→ 继续完善企业建档
→ 企业身份
→ 业务边界
→ 证据资料
→ 监测基线
→ 完成建档并开始策划
```

### 2. 选题、内容与发布

```text
选题中心
→ 选择或新增产品 / 业务线
→ 确认业务线默认知识包（企业公共资料 + 业务线资料）
→ 为业务线批量添加关键词
→ 选择种子词并智能拓展
→ 将拓展结果加入问题词库
→ 从客户问题生成正式选题
→ 将选题加入内容计划
→ 在内容计划中确认本次任务的知识范围（继承默认包，可增减资料）
→ 选择适合内容形式的写作智能体并预览其版本、结构与知识规则
→ 从计划创建内容任务
→ 生成文章并查看智能体执行快照与知识引用证据
→ 打开文章并完成内容风控
→ 人工审核通过
→ 选择一个账号组
→ 勾选官网、微信公众号、知乎或头条号
→ 一键发布
→ 在发布运营查看各平台独立结果
```

### 3. 企业知识驱动写作

```text
企业知识
→ 创建文档库或问答库
→ 上传企业资料 / 维护标准问答
→ 审核并发布知识版本
→ 将知识库加入业务线默认知识包
→ 内容计划继承默认包并按任务补充或排除资料
→ 生成前检索已审核知识（首期 RAG）
→ 文章保存 GenerationRun、ArticleCitation 与版本快照
→ 事实不足或冲突时回到知识缺口，不允许无依据补写
```

文档库适合产品手册、案例、资质、网页和内部资料；问答库适合标准客户问题、服务边界、异议处理和官方回答。首期统一采用 RAG 检索，Wiki 知识图谱作为后续增强，不要求运营人员在每次生成时选择底层索引方式。

### 4. 配置写作智能体

```text
内容生产 → 写作智能体
→ 选择内置智能体并复制为自定义智能体，或直接新建
→ 配置角色、风格、文章结构、系统提示词和严格知识模式
→ 绑定适用业务线、内容类型和优先知识库
→ 保存为新的智能体版本
→ 在内容计划中选择该智能体
→ 创建内容任务时冻结 writingAgentSnapshot
→ 每次生成在文章 generationSnapshot 中再次冻结实际执行上下文
```

写作智能体决定“怎么写”，企业知识库决定“依据什么写”，系统模型设置决定“用什么模型执行”。智能体配置的优先知识库只改变内容计划或直接创作工作区知识范围内的召回顺序，不能读取本次范围排除、未审核或跨业务线的知识。

内置智能体不能直接修改，可以复制为自定义智能体后调整；自定义智能体每次修改都产生新版本。停用只会阻止后续计划选择，不影响历史计划、文章和生成证据查看。

### 5. 直接创作与 AI 协作

```text
内容生产 → AI 创作台
→ 选择业务线、主题与写作智能体
→ 确认本次允许使用的知识库 / 文件与知识图片
→ 左侧只保留标题 / 正文编辑画布，直接输入和修改文章文字
→ 手工内容可直接保存为文章草稿，不要求先执行 AI 生成；未映射的企业知识引用保持待核验
→ 需要写新文章时从右侧 AI 协作发起，不在左侧重复放置 AI 生成按钮
→ 在右侧对话中选择智能体，并按需启用联网、临时附件或图片
→ AI 先返回结构或正文修改 proposal
→ 运营人员确认应用后创建文章新版本
→ 重新完成引用核验、风控与人工审核
```

直接创作由 `writingWorkspaces` 保存创作上下文，`aiConversations` 保存对话与待应用提案，`contentAssets` 统一记录临时附件、生成图片和知识库图片。生成时冻结业务线、主题、写作智能体和实际命中的知识版本；直接创作文章的 `content_plan_id` 为 `null`，不能为了兼容计划流程伪造内容计划。

联网结果只作为外部参考，临时附件只在当前工作区授权范围内使用；两者未经入库、审核和版本发布，不能作为企业事实证据。只有已审核知识版本可以生成 `ArticleCitation`。知识库图片保留素材版本、授权范围和来源，但图片本身不能替代文字事实证据。

左侧创作区采用标题 + 富文本正文编辑器，支持直接编辑、基础排版和素材插入；右侧 AI 对话既可以从空白工作区开始写作，也可以针对当前版本提出标题、结构和段落修改建议。桌面端同时展示正文与右侧 AI 对话；窄屏与移动端切换为「正文 / AI 对话 / 文章信息」三个页签，避免横向溢出。

### 6. 运营诊断

```text
运营诊断
→ 新建诊断项目并绑定业务线与所在行业
→ 从问题词库选择真实客户问题并冻结问题集
→ 生成行业策划、信源生态、官网内容或综合诊断报告
→ 查看研究基线、企业实测与实时采样的证据边界
→ 逐项确认建议并回流问题词库、知识缺口、官网 CMS 或内容计划
```

登录后，工作区、诊断项目、冻结问题集、证据、报告与回流动作均通过服务端 API 保存到 SQLite；浏览器 `localStorage` 仅作为暂时无法连接服务端时的容错缓存。Citation Lab 2.0.1 已固定到 commit `81ba1566f70f114e9202b798f8d4525a9329ebd3` 并转换为只读研究库；行业策划与信源生态报告会先计算豆包、DeepSeek、千问、元宝的确定性全局历史事实包，综合诊断再叠加逐问题研究匹配、企业知识库 RAG 与运营快照。调用外部模型前必须由当前用户确认本次数据发送范围；全局历史基线不会被表述成客户行业的实时或直接实证。配置中转凭证后，私有后台通过实例 HMAC 调用中央中转站，后台定时拉取交付并将验证后的结果写入 `diagnostic_evidence(evidence_type=live)` 和 `diagnostic_metrics`；浏览器不接触爱搜 Token 或实例密钥。

### 7. 内容资产引用追踪

```text
文章成功发布到官网或外部平台
→ 服务端自动创建 / 更新内容资产
→ 记录官网与发布助手回传的成功 URL
→ 运营人员可补充其他公开平台 URL
→ 执行可访问性、跳转、canonical 与内容变化检测
→ 在内容资产页持续查看引用追踪状态
```

内容资产及其发布 URL 以服务端 SQLite 为权威数据源。URL 会规范化并移除常见跟踪参数后幂等去重；自动发布 URL 由发布系统维护，手动 URL 可在内容资产页添加、检测和移除。健康检测只访问公开 HTTP/HTTPS 地址，并拒绝本机、内网和私有 IP，避免把该能力变成内网探测入口。对应接口为 `GET/POST /api/v1/content-assets`、`POST /api/v1/content-assets/sync`、`GET /api/v1/content-assets/:id`、`POST /api/v1/content-assets/:id/publications` 以及单条 publication 的检测/删除接口。

## 当前边界

- 正式版以 GEOFlow Laravel 为唯一管理后台。
- 产品采用一企业一套源码部署；当前部署的业务数据、对象存储、队列任务、检索索引和监测数据都保存在企业自己的环境中，不提供多企业切换或共享后台。
- GEORank 只以内部 API 方式提供关键词拓展和低频站点诊断。
- 选题中心新增业务线、关键词、标准问题、正式选题与内容计划实体。计划生产的文章必须保留完整的选题与内容计划来源链；直接创作是独立入口，使用 `writingWorkspaces` 冻结上下文并保持 `content_plan_id = null`，不能伪造内容计划。
- 产品 / 业务线支持统一管理、删除与恢复：完全空白的业务线可永久删除；已有运营数据的业务线采用可恢复删除，停止新的选题、生成和发布，但保留历史文章、发布记录及知识引用证据。
- 企业知识新增文档库和问答库两种内容类型；资料只有在审核发布后才能进入检索。业务线可绑定一个默认知识包，内容计划继承该包并保存本次任务的知识范围快照（可增补或排除资料）。
- 内容生产新增企业级写作智能体。写作智能体保存角色、风格、结构、系统提示词、适用业务线/内容类型及知识调用偏好；内置智能体只读但可复制，自定义智能体修改时产生新版本，停用后历史引用仍然可读。
- 内容计划必须保存 `writingAgentId` 与不可变的 `writingAgentSnapshot`。智能体后续修改不能静默改变已创建的计划；切换智能体重新生成时必须创建新的生成记录和文章 `generationSnapshot`，不能覆盖旧执行证据。
- AI 创作台使用 `writingWorkspaces + aiConversations + contentAssets`：工作区冻结业务线、主题、智能体与知识版本，对话保存消息和待应用 proposal，素材记录附件、生成图片及知识库图片。AI 建议不会直接改写正文，只有运营人员确认应用时才创建文章新版本，并使旧风控与审核结果失效。
- 联网搜索、临时附件、知识库和知识图片具有不同证据等级：联网与临时附件默认只作上下文，已审核知识版本才可成为企业事实引用；知识图片必须保留素材版本和授权来源，且不能单独证明文字事实。
- 写作智能体不授予知识访问权限。实际检索始终受当前企业、业务线、内容计划或直接创作工作区的冻结知识范围及知识审核状态约束；智能体的优先知识库只能在该交集中调整召回顺序，严格知识模式下证据不足必须返回知识缺口。
- 内容生成新增 `GenerationRun`、`ArticleCitation` 和 `ArticleVersionSnapshot`：每次生成记录使用的模型、提示词、知识范围和结果；文章引用保存原文片段、来源、页码/定位和知识版本；发布任务只使用冻结的文章版本快照。
- 首期知识检索采用 RAG；Wiki 知识图谱是后续能力。底层索引实现不能改变文档库/问答库的业务接口，也不能越过当前企业的数据边界。
- 内容风控复用 GEOFlow 的 `clean / warning / blocked` 状态和发布门禁，不使用数值“风险分”。
- 四步企业建档向导和结构化企业档案是围绕 GEOFlow 企业知识流程新增的产品能力。
- Windows 本地发布助手、账号组和平台状态回写是新增能力；平台 Cookie、验证码和浏览器 Profile 只保存在客户电脑。
- 运营诊断已完成固定研究包、诊断项目、冻结问题集、企业运营快照、报告版本、建议和业务回流，并接入中央中转站的多 AI 平台实时采样、签名交付和 `live` 证据落库。实时排名、提及率等指标只在本次运行具有 verified、带时间戳的 live evidence 时计算；历史研究基线不会被冒充为实时结果。
- 首期发布平台为微信公众号、知乎和头条号，官网文章由服务器自身发布。

详细设计见 [系统架构](docs/ARCHITECTURE.md) 与 [源码能力映射](docs/SOURCE-MAPPING.md)。

Demo 服务端的真实模型生成契约与调用示例见 [AI 生成接口](docs/ai-generation-api.md)。
