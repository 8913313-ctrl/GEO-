# 桐灼 GEOFlow 本地发布助手

这是桐灼自有的 Windows 本地发布器。它安装在内容运营人员的电脑上，负责接收 GEOFlow 的分发任务、调用本地平台适配器，并把执行结果回写到 GEOFlow。平台密码、Cookie、验证码和浏览器登录态只保存在本机，不上传到客户服务器。

## 安装

1. 安装 Node.js 20 或更高版本。
2. 双击 `start.cmd`。第一次运行会安装 Node 依赖、Chromium 和本地平台适配器。
3. 浏览器与助手页面打开后，访问 `http://127.0.0.1:19180`。

安装脚本会把本地平台适配器放入 `vendor/wechatsync-2.0.9`。它是桐灼发布流程的底层兼容组件，不会作为原同步页面使用。适配器目录缺失时，可在助手页面重新指定一个包含 `manifest.json` 的目录。

## 连接 GEOFlow

1. 在客户 GEOFlow 管理后台进入“发布助手”页面，生成配对码或专用 API Token。
2. 创建一个专用 Token，勾选 `articles:read` 和 `articles:write`，建议设置有效期。
3. 将连接地址和 Token 粘贴到本机发布器，不要发给其他人。
4. 点击“保存设置”和“连接 GEOFlow”。
5. 点击平台目录中的平台名称，在当前电脑的隔离浏览器窗口中完成登录。
6. 点击“检测本地适配器”，确认本地发布引擎已就绪。

当前接入的平台目录包含主流内容、技术知识、财经研究、产品运营和内容工具等分组，共 29 个入口。

## 发布流程

1. 在 GEOFlow 中创建并发布文章，任务需要绑定“桐灼多平台发布包”渠道。
2. 本地发布器会定时读取分发队列。
3. 点击任务的“开始执行”。本地发布器会领取任务，并在本机浏览器中调用桐灼平台适配器。
4. 在发布助手的“执行模式”中选择“直接发布”或“仅保存草稿”。
5. 直接发布模式会在本地浏览器逐个平台打开编辑页，尝试执行最终发布；验证码、风控或页面改版时会自动回退为草稿状态。
6. 回到助手确认结果，必要时点击“保留草稿”或“标记已发布”，状态会回写 GEOFlow。

账号登录、Cookie 和验证码只保存在本地浏览器。直接发布依赖各平台当前页面结构，不同平台的页面改版、验证码、风控和内容审核仍可能要求人工处理。

## 数据位置

- `.data/config.json`：GEOFlow 地址、Token 和适配器目录，仅保存于本机。
- `.data/browser-profile/`：助手自己的浏览器登录态。
- `vendor/wechatsync-2.0.9/`：本地平台适配器文件。
