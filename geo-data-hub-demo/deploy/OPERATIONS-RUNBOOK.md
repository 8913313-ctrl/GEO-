# 桐灼中央中转平台运行手册

## 告警分级

- `RELAY_UNREACHABLE` / `RELAY_NOT_READY`：P1。先检查 Node、Nginx、证书和磁盘；停止新客户提交，保留队列，不直接改数据库。
- `RELAY_PROVIDER_UNHEALTHY` / `RELAY_PROVIDER_PROBE_FAILED`：P1。检查统一 AIDSO 账号余额、Token 状态和上游故障；不要自动重提 `submission_uncertain`。
- `RELAY_ATTENTION_ITEMS`：P2。进入运营后台查询任务项，按爱搜侧 reqId 进行人工对账。
- `backup verify` 非零：P1。立即保留最近一次成功备份，暂停清理旧备份，并在隔离目录验证恢复；不得把未验证快照标记为可恢复。

## `submission_uncertain` 对账

1. 在运营后台打开“人工对账”，记录爱搜后台查询时间、工单或 reqId。
2. 已确认未受理：选择“退款并终止”，填写依据；系统释放冻结积分并写入审计。
3. 已确认受理：录入 reqId，选择“继续轮询”；不得再次提交。
4. 明确未创建任务：选择“安全重新提交”；只有未结算且系统确认可以重试时才允许。
5. 每次结论必须包含操作人、原因和上游依据。禁止直接修改 SQLite 账本。

## 交付死信

交付死信只表示客户实例未能落库并 ACK，不代表上游检测失败。确认客户服务端数据库已恢复、实例状态为 active 后，填写核查说明并“重新交付”；该操作不重新检测、不重复扣费。连续失败时暂停实例并升级 P1/P2，不要循环点击重投。

## 实例凭证事件

- 首次签发：只在受保护的 HTTPS 管理响应中交付一次 `clientSecret`，写入客户服务端 Secret Manager 后立即从终端和工单清除。
- 正常轮换：先部署新密钥到客户服务端，验证签名和拉取，再调用轮换接口；旧版本立即失效。
- 泄露处置：立即吊销实例，确认任务和交付状态，重新签发新实例或新密钥；审计记录中填写泄露范围。
- 客户停用：先暂停阻止新任务，处理剩余租约和交付，再永久吊销。吊销不可逆。

## 备份恢复

每日备份、每周自动验证、季度隔离恢复演练。恢复顺序：冻结发布 → 停止 relay → 在目标环境注入原主密钥 → `ops:verify-backup` → `ops:restore --force` → 启动并检查 `/health/ready`、账本摘要、客户实例签名和交付 outbox → 解除冻结。主密钥不在默认备份内，丢失主密钥时不要尝试“生成新密钥恢复”。

## 变更与审计

管理员根 Token 只从 Secret Manager 注入。轮换后重启服务会撤销所有浏览器会话；验证新 Token 后再清除旧文件。所有充值核验、退款、重试、交付重投、实例状态和密钥事件必须在管理员审计中可追溯。
