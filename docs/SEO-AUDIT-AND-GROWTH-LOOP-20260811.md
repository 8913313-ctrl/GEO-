## 结论摘要

主站的基础抓取能力总体可用：25 个 sitemap URL 均返回 200，canonical 自引用，JSON-LD 可解析，404 页面正确返回 404 并设置 `noindex,follow`，站内抓取未发现失效链接或资源。HTTPS、HTTP 到 HTTPS 跳转、安全响应头、语义结构、键盘焦点和减少动画支持也已具备。

但当前还不是一个完整的“私有化 GEO 系统获客站”：公开页面没有清楚说明系统交付、独立部署、功能、权限、使用流程、演示或选型页面；首页与服务页主要出售 GEO 服务、企业 AI 和短视频运营，受众又明显偏工业品与制造业。搜索主题、价值主张、目标受众和核心转化因此没有对齐。

本轮已修复一个真实 P0 可用性问题：Caddy 宣告 HTTP/3，但 Docker 未发布 UDP 443，默认 Chrome 桌面端与移动端均复现 `ERR_CONNECTION_CLOSED`。现已停用 HTTP/3 宣告，保留 HTTP/1.1 与 HTTP/2；默认 Chrome、真实浏览器和 HTTP/2 请求均恢复。

另有一个尚未执行的 P0 内容风险：`/insights/ke59jzq5/` 发布了无法由现有材料核验的服务商榜单、模拟测试、评分、价格和推荐结论。处理它会涉及正文、sitemap、内部链接和可能的索引历史，必须先确认高风险处置方案。

## 2. 价值主张或内容方案

### 推荐价值主张

候选主张：

> 把企业事实、客户问题、内容生产、审核发布和效果复盘放进同一套 GEO 内容运营系统。

该主张只能承诺“组织与工作流能力”，不能承诺固定排名、AI 推荐、曝光量或成交结果。页面证据应来自真实系统能力：知识库、问题词库、内容计划、写作智能体、审核门禁、发布记录、来源证据和版本快照。

### 最小产品内容结构

1. 产品总览：系统解决什么问题、适合谁、不适合谁。
2. 核心工作流：企业事实 → 客户问题 → 内容计划 → 生成/编辑 → 审核 → 发布 → 复盘。
3. 角色页：市场部、内容运营团队、营销服务商各自的任务、权限和成果物。
4. 功能页：知识、问题词库、内容生产、审核、发布、监测和归因。
5. 部署与安全：一企业一部署的真实模式、数据位置、账号权限、备份、恢复和退出机制。
6. 演示/咨询：明确用户会得到什么，不使用“诊断”包装无法核验的自动结果。
7. 真实证据：产品截图、可核验流程、文档更新时间、企业主体和负责人；没有客户授权时只写“典型实施场景”。

### 内容真实性门禁

- 第三方排名、评分、价格、测试结果必须附原始记录、日期、样本、方法和责任人。
- 没有客户授权的内容不得称为“客户案例”或“经过审核的公开案例”。
- 演示内容必须显式标注，并从 Article/FAQ 等结构化数据中避免表达为正式研究结论。
- `llms.txt`、sitemap、RSS 与页面必须共享同一发布门禁，不能机器入口继续暴露已下线内容。

## 3. 转化路径与执行动作

### 当前路径

`访问主站 → 服务/内容页面 → /contact/ → 提交姓名和电话 → site_contact_leads`

当前表单能够写入数据库，已有 1 条来源为 `/contact/` 的记录。问题在于：

- `source_url` 由隐藏字段优先生成，通常只保留路径，会丢失 UTM 和点击 ID。
- 不保存入口页、首次/末次 referrer、UTM、渠道码、点击 ID、会话 ID 或落地页快照。
- 没有线索有效、商机、成交和收入的后续状态，因此无法建立业务归因。
- 表单收集电话和企业信息，但页面没有可见的隐私用途、保存期限或政策入口。
- 目标是销售私有化系统，但 CTA 主要是“预约业务诊断”，没有产品演示、部署评估或角色化咨询入口。

### 推荐归因数据契约

创建线索时保存不可变来源快照：

```text
landing_url
source_url
first_referrer / last_referrer
utm_source / utm_medium / utm_campaign / utm_content / utm_term
gclid / msclkid / baidu-related click id（仅在确有来源时）
channel_code
session_id（第一方随机 ID，不写入敏感身份）
consent_version / consent_at
created_at
```

线索后续至少增加：`new → contacted → qualified → opportunity → won/lost`，并记录状态时间。成交金额只来自 CRM/合同，不从页面行为推算。

### 执行顺序

1. 已完成：修复 HTTP/3 错误宣告，恢复默认 Chrome 访问。
2. 需确认后立即处理：冻结或修订无法核验的榜单文章；同步首页推荐、sitemap、RSS 和 llms。
3. 接入百度搜索资源平台并建立 7/28/90 天基线；如业务仅面向中国大陆，优先百度而不是先上 GA4。
4. 设计第一方归因字段与隐私说明，先记录来源，不改变表单主流程。
5. 以保留现有 URL 为前提，先建立私有化系统产品总览与角色页，再小批量调整首页标题、H1 和 CTA。
6. 清理孤页和空栏目；涉及 301、canonical、sitemap、noindex 时逐 URL 审批。

### 必须分开的指标

- 曝光：搜索曝光、可查询关键词数、索引页面数。
- 点击：自然点击、CTR、自然落地页访问。

- 线索：提交数、有效线索数、有效线索率、首次响应时间。
- 商机：进入机会阶段数量、赢单/丢单原因。
- 成交：成交数、合同金额、来源快照；不得用流量代替成交。
- 技术：5xx、真实 404、抓取异常、LCP、INP、CLS、移动/桌面差异。
