## 重新提炼后的结构

此前的 16 条规则主要回答“如何以证据方式做 GEO”。本轮新增 12 条规则，回答“一个可销售的 GEO 系统如何稳定运行”。两者应并存，不应互相替代：

| 层 | 主要内容 | 是否能直接作为客户效果承诺 |
|---|---|---|
| GEO 方法层 | 企业事实、问题地图、内容、信源、采样、风险 | 否 |
| 工程产品层 | 能力注册、路由、产物协议、权限、回滚、测试 | 否 |
| 研究参考层 | 数据集、论文、报告、生态观察 | 否；只能标注研究范围和局限 |
| 客户项目层 | 建材/机械企业的主体、产品、案例、联系人、采样结果 | 只能在该客户项目中使用 |

## 本轮可进入候选池的规则

1. 能力注册表必须声明状态、输入、输出和未实现状态。
2. 单一意图进入最小能力；多阶段请求才进入稳定工作流。
3. 每次运行生成自包含产物、证据账本、质量报告和运行清单。
4. 来源报告、可复现实验、代理指标与描述性测量分层。
5. 离线测量与实时平台连接器分离，实时操作要求明确授权。
6. 内容必须绑定证据；证据不足保留未知状态。
7. 网站诊断默认只读，范围限于用户明确提供的 URL。
8. SEO 语法、资格、实际展示、AI 引用和业务结果不能混为一层。
9. 改代码、CMS、发布器或账号前必须有授权、回滚和复查记录。
10. 内部开发和客户交付按阶段推进，不能自动跨阶段。
11. 工程评测、数据集与开源 Skill 不构成客户效果承诺。
12. AGPL、MIT、Apache、数据集和文档的许可边界必须分别处理。

## 许可证结论

- `GEOHub` 当前公开标明为 `AGPL-3.0-only`，因此只能作为设计参考；除非取得适当商业许可或完成法律审查，不能把它的代码复制到本产品。
- `qiaomu-seo` 与 `Waza` 标明为 MIT，可作为工程参考；实际复制任何代码前仍需保留原始许可证与署名。
- 已有 `GEOFlow` 为 Apache-2.0、`yao-geo-skills` 为 MIT；使用时仍应按具体文件及 notices 审核。
- 报告、飞书文档、公众号文章、数据集和资源页没有在本轮取得完整正文授权，维持 `review-only` 或 `quote-or-summary-only`。
