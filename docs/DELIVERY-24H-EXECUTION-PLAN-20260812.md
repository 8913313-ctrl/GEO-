# GEO 私有部署交付版：持续执行计划

> 2026-08-12 更新：24 小时仅保留为首轮推进节奏参考，不再作为截止时间。项目以本文放行门槛全部满足、真实测试证据齐全并可独立安装交付为结束条件。

## 目标

在 `codex/qa-fixes-20260812` 分支上，把当前系统推进到可向单个客户整套交付的私有部署 GEO 产品：GEO 能力作为跨行业底层，客户资料、问题、内容和官网模板可配置，后台可控制客户官网发布。

## 交付原则

- 单客户私有部署，不建设 SaaS 租户计费体系。
- GEO 方法论、提示词、质检规则和证据资产版本化、可审计。
- 行业差异由客户资料、业务线、问题、内容和官网视觉模板表达，不复制行业专用后台逻辑。
- 客户官网不得出现桐灼、测试客户或其他客户数据。
- 所有发布动作可审核、可回执、可回滚；空项目和失败流程必须可理解。

## 阶段与任务

### T+0～2 小时：交付基线（P0）

- 记录分支、提交、端口、启动参数、数据库和已知阻塞。
- 运行现有静态检查与闭环脚本，保存结果到 `docs/baseline/`。
- 明确本轮只修复影响新客户建档、内容生产、官网发布、数据隔离和交付安装的问题。

验收：后台和官网可启动；基线命令可重复；失败项有责任人和复现方式。

### T+0～6 小时：新客户核心闭环（P0）

- 新公司建档、行业/产品资料、知识库、客户问题初始化。
- 诊断 → 规划 → 生成 → 质检 → 审核 → 发布 → 官网快照回读。
- 修复空知识库、旧客户 AI 快照、工作台身份、官网健康状态等数据边界问题。

验收：建材、UPS、美妆三种新客户均能完成一条内容从输入到官网发布；租户数据不串。

### T+2～8 小时：GEOFlow 高价值能力（P1）

- 知识切片和语义规划入口。
- 提示词/模型 Provider 配置、失败重试、调用记录。
- 草稿池、审核状态、发布回执、失败重试和人工发布工单。
- sitemap、robots、llms.txt、Schema、RSS 等机器入口。

验收：每项能力都有 API/脚本级检查；不引入 24 小时内无法运维的外部基础设施。

### T+4～12 小时：官网模板体系（P1）

- 建立模板注册表和统一 CMS 数据契约。
- 至少提供专业服务、工业/建材、UPS/能源、美妆/消费品四套模板。
- 后台可预览、切换、发布；切换只改变视觉和信息架构，不改变客户业务数据。
- 每套模板验证桌面、移动端、键盘焦点、空数据和真实客户身份。

验收：同一客户切换四套模板均能生成独立快照；无硬编码桐灼文案。

### T+8～16 小时：测试与安全（P0/P1）

- 正常、空值、非法格式、超长、重复提交、乱序和并发场景。
- API 参数、认证、越权、注入、文件上传、敏感信息泄露检查。
- 数据一致性、快照回滚、备份恢复、资源限制和慢操作检查。
- 真实浏览器完成至少三行业客户流程。

验收：Critical/High 缺陷为 0；Medium 缺陷均有规避方案和记录；测试证据可复查。

### T+16～22 小时：交付打包（P0）

- 私有部署安装、配置校验、启动/停止、健康检查。
- 生成客户配置样例、数据库迁移/备份/恢复说明和运维手册。
- 执行全量回归、构建和产物完整性检查。

验收：在干净目录按文档可安装并启动；发布快照和备份可恢复。

### T+22～24 小时：最终放行（P0）

- 主 Agent 审查所有改动和测试结果。
- 标记未完成项、风险和后续迭代，不以时间到期替代质量门槛。
- 仅在放行条件满足后提交分支并汇报交付清单。

## 并行分工

- `core_flow_fixes`：核心业务闭环与数据边界修复；不得提交。
- `geoflow_gap_analysis`：GEOFlow 对标、复用边界和优先级建议；只读分析。
- 主 Agent：计划、模板实现、审查、回归、交付和分支提交。

## 放行门槛

1. 新客户可独立建档并完成内容发布。
2. 官网由后台发布控制，正式站点状态可实测回读。
3. 客户身份、知识库、文章和快照不跨客户串联。
4. 四套模板共用 CMS 契约且可切换。
5. GEO 底层资产有版本、质检规则和证据来源。
6. 安装、备份、恢复和健康检查可执行。
7. Critical/High 缺陷为 0，测试证据和已知风险已归档。
