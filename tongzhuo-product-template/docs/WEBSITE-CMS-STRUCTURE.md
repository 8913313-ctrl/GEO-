# 官网 CMS 与 GEO 运营后台结构

本文档定义桐灼企业智能运营平台的后台结构，目标是把官网、内容、GEO运营、线索和分发做成可复制交付的产品模板。

## 一、后台总结构

```text
桐灼企业智能运营平台
├─ 产品总览
├─ 官网运营 CMS
│  ├─ 官网概览
│  ├─ 页面管理
│  ├─ 行业资讯
│  ├─ 表单线索
│  ├─ AI抓取设置
│  └─ 全站设置
├─ GEO运营后台
│  ├─ GEO工作台
│  ├─ 内容资产
│  ├─ 发布分发
│  └─ 数据复盘
└─ 系统管理
   ├─ 系统配置
   ├─ 账号权限
   ├─ API Token
   └─ 操作日志
```

## 二、官网 CMS 应有能力

官网 CMS 是给非技术运营人员使用的后台，不应该让用户直接理解源码文件。

当前第一版已经拆分为：

- 官网概览：查看页面、文章、线索、AI文件状态，并提供日常动作入口。
- 页面管理：管理官网公开页面、首页三项服务卡片和 FAQ 问答库。
- 页面编辑器：编辑页面 SEO 标题、描述、首屏标签、主标题和主文案。
- 全站设置：维护公司主体、联系方式、官网域名、地址、页脚内容。
- AI抓取设置：检查 sitemap.xml、robots.txt、feed.xml、llms.txt、llms-full.txt。
- 行业资讯：继续使用 GEOFlow 文章中心，发布后同步到官网资讯页面。
- 表单线索：继续使用客户线索管理，承接官网提交信息。

## 三、二期产品化改造

当前版本为了保护线上系统，仍保留静态 HTML 写回逻辑。二期要把“文件编辑”升级为“数据库内容 + 模板渲染”：

```text
Design Template
+ Site Settings
+ Site Pages
+ Page Blocks
+ Media Assets
= Customer Website
```

建议数据实体：

- `sites`：客户站点。
- `site_settings`：公司、域名、联系方式、SEO 默认信息。
- `site_pages`：页面基础信息、路径、状态。
- `page_blocks`：页面模块内容，如首屏、服务卡片、案例、FAQ、联系表单。
- `page_versions`：草稿、发布版本和回滚记录。
- `navigation_items`：导航和页脚菜单。
- `media_assets`：图片、视频、文件素材。

## 四、GEO 与官网的关系

文章中心是官网 CMS 和 GEO 运营后台的连接点：

```text
企业资料
→ 知识库/关键词/选题
→ GEO任务
→ 文章中心
→ 官网行业资讯
→ AI抓取文件更新
→ 分发任务
→ 数据复盘
```

一篇文章只保留一条主记录。GEOFlow 负责生产和审核，官网负责公开展示，分发管理负责同步到外部平台。

## 五、交付原则

- 官网前台必须服务端可读，不依赖登录和客户端脚本才能看到核心内容。
- 所有公开页面都要有清晰标题、描述、正文、结构化数据和内链。
- 后台按钮必须能真实完成动作，不能只是演示入口。
- 面向客户复制时，只替换配置、页面内容、素材和域名，不复制临时文件。
- 不在官网展示服务价格。
