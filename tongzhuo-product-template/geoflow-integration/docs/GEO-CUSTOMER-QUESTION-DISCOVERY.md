# GEO 客户问题与选题生成规范

## 目标

本系统不把关键词直接改写成文章标题。关键词只用于确定客户可能关心的语义范围；真正进入内容生产的是“客户会直接向 AI 提出的完整问题”。

标准链路：

`业务画像 → 种子关键词 → 八维问题候选 → 人工确认 → 选题 Brief → 企业知识检索 → 文章生成 → 人工审核`

## 姚金刚源码中可复用的逻辑

### GEORank

`backend/app/services/keyword_expansion.py` 提供了两项基础能力：

1. 根据种子词识别企业服务、教育培训、本地服务、电商品牌、内容媒体等业务画像，并为不同画像配置目标用户和禁用词。
2. 按语义、场景、商业意图、推荐榜单、产品评测、品牌关联、问答长尾、技术方案八个维度拓词，并给出推荐价值和商业价值。

它的输出仍是扩展词，不是完整客户问题，也没有问题库、选题 Brief 或证据要求。因此本系统保留“画像 + 八维覆盖”，不照搬其词项即选题的做法。

### GEOFlow

`app/Services/GeoFlow/UrlImportProcessingService.php` 的 URL 采集流程先从清洗后的真实资料提取知识和关键词，再围绕是什么、为什么、怎么做、选型、对比、指南、清单、FAQ、场景和趋势生成标题；同时要求标题服务于 AI 搜索中的比较、采购、实施或运营决策，并禁止无证据的“第一、最好、领先”。

它证明内容应遵循“事实优先”，但普通 `TitleAiGenerationService.php` 仍可能生成泛标题，且标题与来源关键词不一定严格对应。因此本系统把 `customer_question` 与 `editorial_title` 分开保存。

## 本系统补全的方法

### 1. 业务画像

优先读取业务线配置中的：

- `business_profile`
- `target_users`
- `blocked_terms`
- 产品或服务范围
- 客户角色、地域、预算、交付方式和适用边界

未配置时才根据业务线名称、描述和种子词推断画像。推断结果必须允许运营人员修改。

### 2. 八维问题生成

默认每个栏目生成 5 个问题：

| 维度 | 要解决的客户判断 |
| --- | --- |
| 语义拓展 | 概念、边界、关系、差异 |
| 场景覆盖 | 特定行业、阶段或约束下是否适用 |
| 商业意图 | 预算、采购、服务范围、交付和验收 |
| 推荐榜单 | 如何建立比较和筛选标准 |
| 产品评测 | 如何评价产品、服务或方案是否合适 |
| 品牌关联 | 企业或产品能力如何对应客户问题 |
| 问答长尾 | 客户会直接输入 AI 的自然长尾问法 |
| 技术方案 | 实现、集成、流程、风险和验收 |

### 3. 每条问题的结构

模型必须返回：

- `question`：客户可直接输入 AI 的完整问题
- `source_keyword`：严格对应的来源关键词
- `dimension`：八维之一
- `intent`、`decision_stage`
- `asker_role`、`trigger_scenario`
- `expected_answer`
- `follow_up_questions`、`query_rewrites`
- `evidence_requirements`
- `recommendation_score`、`business_score`
- `reason`

分数只表示内容运营优先级，不代表搜索量、真实用户数据或 AI 引用增长。

### 4. 问题质量门

候选问题必须同时满足：

1. 是完整自然语言问句，脱离上下文仍能理解。
2. 体现角色、场景、阶段或决策任务中的至少两项。
3. 一条只解决一个主要判断。
4. 不是“关键词 + 是什么/怎么做”的机械拼接。
5. 与当前业务画像匹配，不包含画像禁用词。
6. 不声称来自真实用户或真实搜索量，除非系统确有相应数据来源。
7. 不虚构价格、排名、案例、数字、资质或效果承诺。
8. 与当前业务线已有问题语义不重复。

模型缺少某个维度时只允许再请求一次补全。补全后仍不足 5 条则明确报错，不能用模板静默伪造。

### 5. 问题到选题

一个主问题只生成一个选题 Brief。对运营人员开放编辑的字段只有：

- 选题标题
- 内容方向
- 用户意图

系统内部继续保存来源问题、决策阶段、回答大纲、追问、证据要求、适用边界和质量评分。编辑标题不得改变来源问题的核心判断。

### 6. 选题到文章

生成文章前必须检索企业知识库，并把每个事实绑定到可追溯引用。文章结构至少包含：

1. 2–3 句直接答案
2. 判断依据及引用
3. 适用对象和条件
4. 对比或选择标准
5. 执行步骤
6. 风险、限制和不适用边界
7. FAQ 与自然追问
8. 来源和更新时间

知识不足时应创建知识缺口并停止生成，或明确省略相应事实；不得让模型自行补写企业事实。

## 状态流转

| 对象 | 生成后 | 人工确认后 | 向下流转后 | 不再使用 |
| --- | --- | --- | --- | --- |
| 问题 | `candidate` | `active` | `promoted` | `archived` |
| 选题 | `candidate` | `active` | `planned` | `archived` |

默认列表只展示 `active`。问题进入选题库、选题进入计划后，上一步默认列表自动消失，但记录和来源关系仍可在归档/历史状态中追溯。
